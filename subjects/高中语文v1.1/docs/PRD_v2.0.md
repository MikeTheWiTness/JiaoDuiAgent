# 高中语文校对工具 v2.0 PRD

## Problem Statement

高中语文 v1.1 校对工具存在以下问题：

1. **接口不兼容**：方法签名与核心框架不一致，可能导致程序无法正常运行
2. **模式单一**：只有讲义/试卷两种模式，无法满足灵活的校对需求（如临时校对一段文字、一首诗、一篇文言文）
3. **分割方式僵硬**：只能按标题/题号等规则分割，无法处理"一篇文章+几道小题"作为一个校对单元的语文场景
4. **缺少专业工具**：文言文和诗歌校对是语文的核心场景，但缺少针对古籍原文检索的专业工具适配
5. **无批注评审能力**：实际工作中常有"实习生先写批注、资深人员评审"的场景，现有工具不支持
6. **版本落后**：v1.1 与高中物理 v1.8 差距较大，没有跟上架构演进

## Solution

高中语文校对工具从 v1.1 升级到 v2.0，在现有 GUI 模板上扩展，新增以下核心能力：

1. **四种校对模式**：讲义 / 试卷 / 自由校对 / 批注评审
2. **四种分割方式**：不拆分 / 普通规则分割 / 智能分割（LLM 识别） / 人工标记分割
3. **文言文/诗歌三层校对架构**：前置原文搜索 + 程序自动差异比对 + LLM 判断与综合校对
4. **识典古籍与搜韵网专业适配**：针对语文校对场景优化古籍原文检索
5. **批注评审模式**：支持带批注的 Word 文档，LLM 评判已有批注并补充发现遗漏错误
6. **完整 PDF 报告**：所有模式均生成详细 PDF 校对报告

## User Stories

### 自由校对模式

1. 作为语文教研员，我想粘贴一段文字 + 上传几张图片，直接进行校对，这样不需要先整理成 Word 文件
2. 作为语文教研员，我想上传一个 Word/MD 文件进行自由校对，这样灵活处理各种格式的文档
3. 作为语文教研员，我可以选择"不拆分"，把整份内容作为一个校对单元，这样处理短内容更方便
4. 作为语文教研员，我可以选择"普通规则分割"，按题号/标题分割，这样处理结构化文档更快
5. 作为语文教研员，我可以选择"智能分割"，让 LLM 自动识别完整题目单元，这样处理非结构化文档更准确
6. 作为语文教研员，我可以选择"人工标记分割"，按我预先在文档中标记的边界分割，这样完全由我控制分割结果
7. 作为语文教研员，自由校对也能生成详细的 PDF 报告，这样可以存档和分享

### 智能分割

8. 作为语文教研员，智能分割能自动识别"一篇文言文+几道小题"作为一个校对单元，这样校对时有完整上下文
9. 作为语文教研员，智能分割能自动丢弃引言、说明、过渡文字等非题目内容，这样不用手动清理
10. 作为语文教研员，如果智能分割第一次失败，系统会自动重试一次，这样成功率更高
11. 作为语文教研员，如果智能分割两次都失败，系统会降级为"不拆分"，这样不会卡死
12. 作为语文教研员，智能分割使用 `<problem></problem>` 标记原文，这样不会篡改原文内容

### 人工标记分割

13. 作为语文教研员，我可以在 Word 或 MD 文件中用 `###### 题目开始 ######` 和 `###### 题目结束 ######` 手动标记题目边界
14. 作为语文教研员，程序会校验标记是否成对，不成对时报错提示我，这样能及时发现错误
15. 作为语文教研员，未被标记的内容会被自动丢弃，这样引言和说明不用手动删
16. 作为语文教研员，人工标记分割在所有模式下都能用，这样最灵活

### 文言文/诗歌校对

17. 作为语文教研员，校对文言文时系统会自动到识典古籍检索原文，这样不用我手动搜
18. 作为语文教研员，校对诗歌时系统会自动到搜韵网检索原文，这样不用我手动搜
19. 作为语文教研员，程序会自动比对原文和待校文本，列出所有字面差异，这样一个字都不会漏
20. 作为语文教研员，LLM 会判断哪些差异是真错误，哪些是版本差异/通假字/异文，这样不用我自己分辨
21. 作为语文教研员，如果前置搜索不到，LLM 还可以自己用搜索工具补搜，这样有兜底
22. 作为语文教研员，如果专业网站搜不到，还可以全网搜索，这样覆盖面最全
23. 作为语文教研员，文言文/诗歌之外的题目（成语、病句、文学常识等），LLM 可以自主决定要不要搜索，这样灵活高效

### 批注评审模式

24. 作为语文教研员，我可以上传带有人工批注的 Word 文档，让 LLM 评审这些批注
25. 作为语文教研员，系统会把批注内容插在原文对应位置，这样 LLM 能清楚看到批注在哪里
26. 作为语文教研员，LLM 会逐条评判批注的正确性（正确/有误/部分正确），这样我能快速判断实习生的工作质量
27. 作为语文教研员，LLM 还会补充发现遗漏的错误，这样校对更全面
28. 作为语文教研员，批注评审也支持所有分割方式，这样大文档也能处理
29. 作为语文教研员，批注评审有专门的 PDF 排版（逐条展开式），这样阅读体验好

### 通用功能

30. 作为语文教研员，如果内容里有答案，LLM 会一起校对答案的准确性，这样更全面
31. 作为语文教研员，如果内容里没有答案，LLM 会专注于题干本身的校对，这样不会做无用功
32. 作为语文教研员，工具版本号是 v2.0，这样我知道是大版本升级
33. 作为语文教研员，所有功能都在同一个 GUI 里，不用切换程序，这样学习成本低

### 测试相关

34. 作为开发者，识典古籍适配器有独立测试，这样能验证搜索和抓取是否正常
35. 作为开发者，文言文/诗歌识别有独立测试，这样能验证识别准确率
36. 作为开发者，自动差异比对有独立测试，这样能验证 diff 的准确性
37. 作为开发者，智能分割有独立测试，这样能验证分割逻辑
38. 作为开发者，人工标记分割有独立测试，这样能验证标记解析
39. 作为开发者，Word 批注提取有独立测试，这样能验证批注提取的准确性
40. 作为开发者，每个模块都能独立运行和测试，这样调试方便

## Implementation Decisions

### 整体架构

- 复用现有 DefaultApp GUI 模板，通过 `_get_ui_features` 扩展功能开关和模式
- source_mode 从 2 种扩展为 4 种：讲义 / 试卷 / 自由校对 / 批注评审
- 分割方式从 2 种扩展为 4 种：不拆分 / 普通规则 / 智能分割 / 人工标记
- 版本从 v1.1 升级到 v2.0，在原目录上迭代

### 模块划分（新增模块均为可独立测试的深模块）

**1. 识典古籍适配器**（在 shared/web_tools.py 中扩展 WebFetchTool）
- 新增 `_fetch_shidianguji(url)` 方法
- 自动识别识典古籍 URL，使用专用抓取逻辑
- 流程：搜索结果页 → 取第一条 → 进详情页 → 提取完整原文
- 接口与现有 `_run` 保持一致，调用方无需感知

**2. 文言文/诗歌校对工具集**（新增 shared/chinese_classics_tools.py）
- `detect_text_type(md_text) -> "classical" | "poetry" | "modern"`：文本类型识别
  - 文言文：文言虚词密度检测（之、乎、者、也、矣、焉、哉...）
  - 诗歌：句式整齐度 + 常见诗歌格式检测
- `search_original_text(text_type, sample_text) -> original_text | None`：前置原文搜索
  - 文言文 → 识典古籍
  - 诗歌 → 搜韵网
- `diff_texts(original, target) -> list[diff]`：自动差异比对
  - 字符级 diff
  - 输出差异列表（位置、原文、待校、差异描述）
- `build_preamble(text_type, original, diff_list) -> str`：生成前置参考原文段落
- 预留独立测试接口，每个函数都可单独调用测试

**3. 智能分割器**（新增 shared/smart_split.py）
- `smart_split(md_text, api_url, api_key, model) -> list[{title, content}]`
- 调用 LLM，提示其在原文中插入 `<problem></problem>` 标记
- 解析 XML 标记，提取每个题目单元
- 失败重试 1 次，再次失败则降级为单单元（全文作为一个单元）
- 预留独立测试接口

**4. Word 批注提取器**（新增 shared/docx_comments.py）
- `extract_comments_to_md(docx_path, output_md_path) -> bool`
- 从 .docx 的 comments.xml 中提取批注
- 找到批注在正文中的对应位置
- 将批注以 `[📝批注N：内容]` 形式插入原文对应位置
- 预留独立测试接口

**5. 人工标记分割器**（新增 core/manual_split.py 或在 defaults.py 中）
- `split_by_manual_markers(md_content) -> list[{content}]`
- 识别 `###### 题目开始 ######` 和 `###### 题目结束 ######` 成对标记
- 校验标记配对，不配对则抛出异常（报错提示用户）
- 未被标记的内容自动丢弃
- 预留独立测试接口

**6. 批注评审 PDF 生成**（在 shared/latex_generator.py 中扩展）
- 新增 `build_comment_review_content(md_content, review_data)` 函数
- 逐条展开式排版：原文 → 逐条评审 → 补充发现
- 与现有 paracol 双栏模板并行
- 预留独立测试接口

### 业务层修改（subject.py）

- 修复接口签名，对齐高中物理 v1.8 规范
- `split_lecture` / `split_exam` 支持四种分割方式
- `proofread_one` 接入前置搜索 + 自动 diff 流程
- 新增批注评审模式的提示词和处理流程
- 新增 `get_ui_features()` 方法自定义 UI

### 配置层修改（config.json）

- 更新题目校对提示词（加入工具说明、三层架构说明、有答案校答案）
- 更新知识校对提示词
- 新增批注评审提示词
- 新增智能分割提示词

### GUI 层修改（ui/default_app.py）

- source_mode 扩展为 4 种
- 分割方式从布尔选项改为下拉选择（4 选 1）
- 自由校对模式下显示文本输入区和图片上传按钮
- 模式切换时动态显隐对应控件

## Testing Decisions

### 测试原则

- 测试外部行为，不测试实现细节
- 每个新增模块都有对应的测试
- 测试用例覆盖正常路径和异常路径
- 优先测试纯函数（不依赖外部 API 的部分），外部 API 相关测试标记为集成测试

### 测试模块

1. **chinese_classics_tools 测试**
   - 文言文识别准确率测试（多篇典型文言文 + 现代文对照）
   - 诗歌识别准确率测试（唐诗、宋词、现代诗对照）
   - 自动差异比对测试（插入字、删除字、替换字、语序调整等场景）
   - 前置搜索集成测试（可选，需联网）

2. **smart_split 测试**
   - 标记解析测试（正常标记、嵌套标记、无标记、标记不配对等）
   - 降级逻辑测试
   - 端到端集成测试（可选，需调用 API）

3. **docx_comments 测试**
   - 批注提取测试（用已知的带批注 docx 文件）
   - 位置插入准确性测试
   - 无批注文件处理测试

4. **manual_split 测试**
   - 正常成对标记分割测试
   - 标记不配对报错测试
   - 无标记报错测试
   - 多段标记测试
   - 标记前后垃圾内容丢弃测试

5. **web_tools 识典古籍适配测试**（集成测试，需联网）
   - 搜索功能测试
   - 详情页原文提取测试
   - 错误 URL 处理测试

### 测试框架

- 使用 Python 标准库 unittest 或 pytest（看项目现有习惯，目前项目没有测试框架）
- 测试文件放在对应模块同级或 tests/ 目录下

## Out of Scope

- 不做独立的 GUI 界面，复用现有 DefaultApp 模板
- 不做实时协作校对功能
- 不做校对结果的版本管理和历史对比
- 不做多用户和权限管理
- 不做 OCR（图片中的文字识别）
- 不做语音校对
- 不做移动端适配
- 不做英文语文校对

## Further Notes

- 所有新增模块均预留独立测试接口，方便后续单独调试和优化
- 文言文/诗歌识别的启发式规则可能需要根据实际使用反馈调整阈值
- 智能分割的效果依赖 LLM 能力，提示词可能需要迭代优化
- 识典古籍和搜韵网的网站结构如果变化，适配代码需要相应更新
- 批注评审模式的 PDF 排版（逐条展开式）为初版，后续可根据实际使用效果调整
