# 0003-文言文诗歌校对采用三层架构

文言文和诗歌校对采用"前置搜索 + 程序自动差异比对 + LLM 判断"的三层架构。

## 背景

文言文和诗歌校对的核心需求是原文比对。仅靠 LLM 自主搜索比对存在两个问题：
1. LLM 可能漏看细微的文字差异（通假字、异文、语序等）
2. 每次都让 LLM 自己搜索，效率低且不稳定

## 决策

采用三层架构，各层职责分离：

**第一层：前置搜索（程序主动）**
- 启发式规则识别文言文/诗歌（文言虚词密度、句式等）
- 文言文 → 识典古籍搜索，提取前几句作为关键词
- 诗歌 → 搜韵网搜索，提取第一联作为关键词
- 搜索成功则拿到完整原文
- 搜索失败不影响后续流程，LLM 可自行补搜

**第二层：自动差异比对（程序计算）**
- 拿到原文后，做字符级 diff
- 输出差异列表（位置、原文、待校、差异点）
- 程序只找差异，不判断对错

**第三层：LLM 判断与综合校对**
- LLM 基于差异列表，判断哪些是真错误、哪些是版本差异/通假字/异文
- LLM 同时完成程序做不了的事：划线/加点与题干匹配、文学常识、典故出处等
- LLM 也可自主调用搜索工具补搜（前置搜不到时）

搜索优先级：识典古籍/搜韵网 → 全网搜索 → LLM 自身知识。

## 后果

- 保证了"一个字都不漏"的差异发现能力
- LLM 专注于判断和语义理解，不做机械比对
- 前置搜索增加了少量耗时（1-2 秒），但提升了校对质量
- 各层可独立测试和优化
