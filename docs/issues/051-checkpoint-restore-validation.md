# Issue 051：快照恢复 —— 四重校验 + 损坏分流 + 图片重编码

**关联 ADR**：[ADR-0029](../adr/0029-proofread-checkpoint-resume.md)（恢复与四重校验 / 图片 / 恢复可见性各节）

---

## What to build

校对启动时自动检测单元内的 `_校对续传.json`：校验通过即从断点续跑（log 单行提示，零弹窗）；不匹配即无痕删除从零开始；损坏即重命名保留现场。完成后，「程序中断后重跑同一单元」不再从头消耗已完成的工具循环 token。

### 检测范围

仅 `enable_checkpoint=True` 的调用路径检测（门控随 Issue 050 落地）；其余调用方行为不变。

### 四重校验，任一不匹配即不恢复

| 校验 | 防的场景 |
|---|---|
| `q_title` | 单元错位 |
| `prompt_hash` | 批注评审与普通校对共用单元目录/题名（prompt 不同）；学科 prompt 迭代后的旧语义快照 |
| `md_hash`（pre_hook 前的原始单元 md 哈希） | 用户编辑题目后重跑 |
| `model` | 换模型后续传（纯文本模型回放含图消息必 400；换模型本身应重开对话） |

### 校验失败分两类处理

- **文件级损坏**（JSON 解析失败 / `schema_version` 不认识 / 缺必需字段）：重命名为 `_校对续传.corrupt.json` 保留——损坏是异常，留排查现场；重命名后不妨碍新一轮快照写入
- **校验不匹配**（四重校验任一失败）：直接删除快照——换模式/改题/换模型是正常操作流转，无痕进行，不留 `.mismatch` 类文件（会随每次正常变更堆积孤儿文件）

### 恢复动作

- `state.load()` 重建 `ProofreadState`，交给工具循环续跑——不重放已完成的工具
- 图片从单元 `images/` 目录按文件名清单重新编码回填（复用校对入口现有编码逻辑：mime 判断 + 大小过滤）；文件缺失时 log 警告、该图降级缺失
- 纯文本模型剥图语义无需恢复路径特判——`model` 校验已保证恢复时模型与快照时相同
- **log 单行提示**：`⏩ 第X题：检测到中断快照（已进行 N 轮工具循环），从断点续跑`——不弹窗（并行多单元会连环弹窗），也不静默（排查 token 用量跳变需要线索）

### 文档同步

- AGENTS.md 中间产物清单补收 `_校对续传.corrupt.json`

## Acceptance criteria

- [ ] 中断后重跑同一单元（同 prompt / 同 md / 同模型）：自动续跑，不重放已完成工具，log 出现续跑提示行
- [ ] 以批注评审模式重跑普通校对的中断单元（或反之）：不恢复，从零开始，快照被删除
- [ ] 编辑单元 md 后重跑：不恢复，从零开始，快照被删除
- [ ] 换模型后重跑：不恢复，从零开始，快照被删除
- [ ] 快照 JSON 损坏 / 版本号不认识：重命名为 `_校对续传.corrupt.json`，从零开始，本轮校对正常完成
- [ ] 恢复的会话中图片从 `images/` 目录重新编码；人为删除一张图片文件后恢复，log 有警告且校对流程不中断
- [ ] 快照恢复后的对话历史继续累加，最终 `_API对话记录.md` / `_校对报告.md` / token 用量含恢复前的轮次与用量（`total_usage` 不清零）
- [ ] 用户删除快照文件后重跑：等价全新校对
- [ ] AGENTS.md 中间产物清单已收录 `.corrupt` 文件名
- [ ] 全量 `pytest` 保持全绿
