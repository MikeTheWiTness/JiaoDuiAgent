# Issue 052：重试携带状态续跑 —— 网络波动不再从零重建对话

**关联 ADR**：[ADR-0029](../adr/0029-proofread-checkpoint-resume.md)（重试语义节）

---

## What to build

网络波动触发 API 重试时，工具循环已完成的调用历史与 LLM 中间结果不再丢失：重试携带已有对话继续，已完成工具不重放；仅首次请求失败（无任何历史）才从零开始。用户视角：长工具循环中途网络闪断，等待退避后从中断轮次附近继续，而不是整题白跑重烧 token。

### 改动范围

- `call_api` 的重试循环：异常分类、重试上限、指数退避、熔断（连续同类型错误 ×3）、Retry-After 优先、三段错误报告——**全部行为不变**（ADR-0021 既有契约）
- 变更的只有重试的起点：从「重建初始 messages」改为「携带 `ProofreadState` 现状续跑」
- 首次请求失败（state 无任何 assistant 历史）仍从零开始，与现状一致
- 工具循环**中途**失败（`_post_chat` 或工具执行抛可重试异常）是本 issue 的主场景

### 与磁盘快照的关系

本 issue 是**内存态**重试语义改造，与 `_校对续传.json` 正交：快照管「进程死了下次重跑」，本 issue 管「进程活着这次重试」。快照保存点（轮次边界）与重试续跑点（异常现场）可能不同轮，两者独立成立、互不依赖。

## Acceptance criteria

- [ ] 工具循环中途注入可重试网络异常（mock）：退避后从已有对话继续，已完成工具不重复出现在 tool_calls_log
- [ ] 续跑后的 token 用量为「中断前累计 + 续跑新增」，不重复计算中断前的轮次
- [ ] 首次请求失败的重试仍从零开始（现状行为）
- [ ] 异常分类 / 重试上限 / 退避 / 熔断 / Retry-After / 错误报告行为逐字不变（既有测试不改动即通过）
- [ ] 不可重试错误（认证失败 / 400）立即停止，不清空已积累的对话记录
- [ ] ADR-0029 状态翻转 + CONTEXT.md 同步已执行
- [ ] 全量 `pytest` 保持全绿
