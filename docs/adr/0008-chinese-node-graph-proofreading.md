# ADR 0008：高中语文校对节点图重构

**状态**：已实现（commit b878670）

**实现日期**：2026-06-29

**相关 ADR**：[[ADR 0005 ReAct 机制核心架构]](0005-react-mechanism-architecture.md)、[[ADR 0006 物理 ReAct 学科化]](0006-physics-react-subject-specialization.md)

## 背景

ADR-0005 落地通用 ReAct 机制后，高中语文采用纯 LLM 自主规划模式：LLM 首轮调用 `plan_update` 声明计划步骤，后续逐项执行。物理学科在 ADR-0006 中重构为固定流程（prompt 写死 9 步），效果显著——消除了"自主规划空转"，让 LLM 把注意力集中在具体校对动作上。

语文是否也适合固定流程？分析发现：**物理是一套流程分大小题，语文是不同文本类型需要完全不同的校对策略**。文言文不能做常规错别字识别（通假字 vs 错字），默写题的核心是逐字比对而非内容判断，写作题不需要标点扫描——物理的"单线固定流程"在语文场景下是错误抽象。

## 决策

**语文校对从"LLM 自主规划"改为"节点图 + 固定分支 todolist"。**

### 节点图结构

```
第 0 步：LLM 识别文本类型（唯一的前置判断点，不做程序预路由）
  │
  ├─ ① 论述类文本阅读（7 步）
  ├─ ② 文学类文本阅读（散文/小说，7 步）
  ├─ ③ 实用类文本阅读（新闻/报告/传记，6 步）
  ├─ ④ 文言文阅读（7 步，不做错别字识别，仅做前置参考逐字比对）
  ├─ ⑤ 古诗词鉴赏（6 步）
  ├─ ⑥ 名篇名句默写（5 步）
  ├─ ⑦ 语言文字运用（8 步）
  └─ ⑧ 写作题（7 步）
```

### 关键设计点

1. **每个分支是独立的小型固定 todolist**。机械检查（标点、题号、格式）在前，主内容校对在后，格式自检 + 输出收尾。

2. **文言文/古诗词分支不做常规错别字识别**。同为汉字，在现代文中是错字、在文言文中可能是通假字——用同一套规则扫描产生噪音。文言文分支的核心是"前置参考逐字比对"（`pre_proofread_hook` 已自动检索权威原文）。

3. **分支内保留一个"主内容校对"步骤**：答案是 LLM 自主判断的核心——选项逻辑自洽性、解析得分点合理性、翻译/鉴赏准确性——这些不能用规则替代，是整个校对流程中价值最高的步骤。固定检查项把形式层兜住，让 LLM 把全部判断力留给这一步。

4. **允许分支切换，但需两阶段确认**：LLM 怀疑类型判断有误时，先声明理由并重新审视原文特征，确认后才切换分支。避免仓促切换造成混乱。

5. **反思机制仅做格式自检**（标记数=原因数、编号格式、段落完整性）。bash 能修的直接修，修不了的打回重做。语文没有 sympy 可程序化验证的内容，不做内容层面的打回重做。

6. **`plan_update` 用法**：第 1 轮 LLM 识别类型后声明对应分支的 todolist，后续逐步标记 completed。不做自主规划，做进度标记 + 切换锚点。

7. **`nudge_template` 置空**（与物理一致）：自检靠 prompt 固定步骤，不依赖工具返回值触发。`nudge_template` 参数保留以备未来使用。

8. **`max_loops` 保持 15**：最长分支 ~8 步，加反思回退和可能的 1-2 次分支切换，15 轮足够。

9. **不需要 `independent_solve`**：语文无客观可计算验证的答案。文言文/诗歌的"独立验证"已通过 `pre_proofread_hook` 的前置参考注入实现。

## 与物理 ADR-0006 的对比

| 维度 | 物理（ADR-0006） | 语文（本 ADR） |
|---|---|---|
| 计划结构 | 单线固定 9 步 | 节点图 → 8 条分支，每条 5-8 步 |
| 前置判断 | LLM 判"是否难题"→ 是否插入独立解题 | LLM 判"文本类型"→ 走哪个分支 |
| 独立验证 | `independent_solve` 工具 | `pre_proofread_hook` 前置参考检索 |
| 反思范围 | 校对动作（sympy error / 独立答案异常 / 格式） | 仅格式自检 |
| 新增工具 | `IndependentSolveTool` | 无（纯 prompt 层改动） |
| nudge | 空串 | 空串 |

## 后果

### 正面
- 不同文本类型走不同的校对策略，避免"文言文被当现代文扫错字"的噪声。
- 机械检查固化为不可跳过的步骤，消除 LLM 自主规划时的遗漏（尤其是标点、题号这类低门槛高频率的错误）。
- 主内容校对步骤集中 LLM 全部判断力，不被形式检查分散注意力。
- 改动面极小：仅重写 `agent_prompt.json`，不改任何 Python 代码。`subject.py`、`plan_tools.py`、`api_client.py` 全部不变。
- 保留旧 prompt 作 fallback 方便 AB 对比。

### 负面
- 8 条分支的 prompt 显著变长，注意力稀释风险。需控制每条分支的步骤描述简洁。
- LLM 自判文本类型存在极小误判概率（但高中语文题型差异大，现代文/文言文/作文几乎不会误判）。
- 分支间切换的两阶段确认增加 token 消耗（但发生频率极低）。

### 风险
- 文本类型误判 → 全流程走错分支。缓解：prompt 判据明确 + 允许分支切换。
- prompt 变长导致 LLM 对后续步骤注意力下降。缓解：每条分支步骤描述精简，关键约束在对应步骤内就近写明。
- 半文半白的近代文可能让 LLM 在文言文/现代文分支间犹豫。缓解：两阶段确认机制 + `max_loops=15` 兜底。

## 不纳入
- 新增语文专用工具（无需求）
- 程序预判文本类型（信任 LLM 自判，待实际效果验证后再考虑）
- `max_loops` 调整（保持 15）
- `nudge_template` 删除（保留参数，全部学科置空）
