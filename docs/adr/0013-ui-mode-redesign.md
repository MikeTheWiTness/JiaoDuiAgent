# ADR 0013：UI 模式重构 —— 从双层下拉到线性步骤

**状态**：草案（待细化）
**日期**：2026-06-30
**决策者**：MikeTheWiTness
**关联**：[[ADR 0012 框架工程债]](0012-framework-engineering-debt.md)

---

## 背景

当前 UI 使用双层下拉——`source_mode`（讲义/试卷/自由校对/批注评审）和 `exec_mode`（完整流程/仅转换/仅拆分/仅校对/仅生成PDF）——产生 12+ 个组合，其中多个组合无意义（如"仅转换" + "自由校对" = 等价于不拆分），多个组合的行为矛盾（如"仅转换"显示了无用的 ReAct 复选框，"仅校对"隐藏了需要的 ReAct 复选框）。

同时存在 5 个具体 bug（详见 ADR-0012 关联讨论）：
1. 清单无法逐项删除
2. "仅校对"模式下 ReAct 复选框隐藏
3. "仅转换"模式下 ReAct 复选框显示
4. MD 文件在完整流程中被重复清理
5. UI 模式混乱，新人学习成本高

---

## 方向（待细化）

将双层下拉改为**线性步骤向导**：

```
步骤 1：输入
  ○ 上传文件（转换 → 拆分 → 校对）
  ○ 选择已拆分的目录（跳过转换和拆分，直接校对/生成PDF）

步骤 2：处理选项（仅步骤1选择"上传文件"时）
  内容类型：○ 讲义  ○ 试卷  ○ 自由校对  ○ 批注评审
  分割方式：[规则/智能/不拆分/人工标记]
  □ 清理表格边框
  □ 提取知识文件夹

步骤 3：输出选项
  □ ReAct 模式
  □ 生成 PDF
  □ 并行校对

步骤 4：执行
  [开始处理]  [中断]  [导出报告]
```

### 待决问题

- [ ] 步骤向导的 UI 框架选型（纯 tkinter or 自定义）
- [ ] 清单的逐项删除交互（右键菜单 or 删除按钮）
- [ ] ReAct 开关的准确位置（步骤 3 or 全局设置）
- [ ] "仅生成PDF"是否仍需要独立入口
- [ ] 向后兼容——现有 `source_mode`/`exec_mode` 的内部枚举是否保留

---

## 时机

本 ADR 为草案，不在 ADR-0010 实现周期内执行。Bug 1-4 的修复不需要等待 UI 重构——可在当前框架内单独修复：

| Bug | 修复方式 | 影响范围 |
|-----|---------|---------|
| 1. 无法逐项删除 | 加右键菜单 or Delete 键绑定 | `default_app.py` |
| 2. "仅校对"无 React | 将 React 复选框移出 `frame_convert_settings` | `default_app.py` |
| 3. "仅转换"显示 React | 同 2 | `default_app.py` |
| 4. MD 重复清理 | `_write_problems_to_dirs` 加参数跳过 clean 生成 | `subject.py` × 6 |

修复 Bug 1-4 的工作量小（~50 行改动），不影响 ADR-0010 的实现。
