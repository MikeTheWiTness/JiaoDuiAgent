# ADR 0006：高中物理 ReAct 机制学科化重构

**状态**：已实现（commit 4bfd29e）
**日期**：2026-06-29
**决策者**：MikeTheWiTness
**相关 ADR**：[[ADR 0005 ReAct 机制核心架构]](0005-react-mechanism-architecture.md)、[[ADR 0007 物理自主解题 Agent]](0007-physics-autonomous-solving-agent.md)

---

## 背景

ADR-0005 落地了通用 ReAct 机制（PlanUpdateTool + 工具循环 + 格式审查），高中物理作为首批接入学科之一，已在 [agent_prompt.json](../../subjects/高中物理v3.0/agent_prompt.json) 中做了学科差异化（加入 6 个符号计算工具说明、磁场偏转工具）。

但实际校对效果在**物理过程复杂的大题**上准确率明显偏低，尤其是**答案/解析的准确性校对**。排查发现，问题不在"物理套用了语文的 prompt"——物理 prompt 已经差异化——而在于 **ReAct 机制的核心设计以"文本校对"为心智模型，与物理校对的难点不匹配**。

### 根因诊断

1. **PlanUpdateTool 的计划模板是文本校对模板，未覆盖"答案正确性"这个物理校对最难的维度**
   - [plan_tools.py:84-99](../../shared/plan_tools.py#L84-L99) 的自查 nudge 是"标记数量=原因数量？段落是否都在？是否漏了错别字/标点"——全是文本校对语言。
   - 物理校对最难的点是**判断题目给的答案/解析对不对**，而现有计划模板里这一项是缺位的，LLM 只会规划"通读→定位→标记→自检"，对复杂大题的答案正确性只能靠模型估算。

2. **prompt 是"代入验证已有答案"范式，缺乏"独立重算"范式**
   - [agent_prompt.json:33](../../subjects/高中物理v3.0/agent_prompt.json#L33) 的核心指令是"答案校验环节中所有数值计算必须调用工具实算，不得凭估算"——这是**代入验证**范式，假设题目答案现成、LLM 只需代入。
   - 物理大题常见情况是**题干/答案本身就有错**，LLM 必须**独立解一遍**才能发现答案错。"代入验证"与"独立求解再比对"是两种根本不同的认知动作，现有 prompt 未区分。

3. **缺乏"独立解题"手段**
   - 主 agent 在校对复杂大题答案时，没有"把答案去掉、用干净上下文独立解一遍再比对"的能力，只能凭模型自身在已看到答案的情况下估算——已被答案污染的判断不可靠。

## 设计原则

**校对是主任务，解题是手段**。物理 ReAct 的计划结构应是**校对检查项 todolist**（错词/格式/解析正确性/…），而非解题链路。只有当校对进行到"解析正确性"这一步、且判定为大题时，才触发"独立解题"作为答案校对的手段。

**独立解题用可替换接口实现**。早期用轻量方式（单次 API 独立解题），未来 ADR-0007 的完整 ReAct 自主解题 agent 开发出来后，只替换接口内部实现，校对主流程不变。

## 决策

### 决策 1：物理校对范式——固定流程 + 逐步进度标记 + 标记前反思

**选择**：物理校对流程**写死在 prompt**（固定检查项顺序，非 LLM 自主规划），LLM 在一个 ReAct 循环里按固定流程走完。`plan_update` 用法从"首轮自主声明完整 todolist"改为"**逐步进度标记 + 纠错回退点**"——每完成一步标记 completed，标记前允许一次轻量反思决定继续还是打回重做。

**物理专用计划模板**（写入 prompt 的"工作流程"段）：
```
1. 错词错字校对
2. 格式问题校对
3. 公式符号/单位/矢量符号校对
4. 题干严谨性/物理情景描述校对
5. 解析验算（用 sympy 工具实算验证解析中的计算步骤）—— 同步判定是否难题
6. 【若难题】剪掉题目答案与上下文，调 independent_solve 独立解题
7. 【若难题】独立答案 vs 题目答案 综合评判
8. 输出校对报告（标记原文 + 修改原因 + 自检清单）
9. 格式审查（检查报告格式，用 bash 修改格式问题）
```

**关键点**：
- 流程**固定写死在 prompt**，LLM 不"自主规划"步骤顺序（物理流程固定，自主规划是空转）。LLM 唯一的自主判断是**第5步时判定是否难题→要不要插入第6、7步**。
- 第 5 步是"代入验证"范式（验证题目解析里的计算对不对），第 6、7 步是"独立重算"范式（不信任题目答案，自己解一遍）。

**进度标记 + 反思机制**：
```
每完成一步 → 标记前反思：上一步结果有没有问题？
   ├ 无问题 → plan_update 标记该步 completed → 进下一步
   └ 有问题 → 打回重做该步（不标记 completed）
```

**反思纠错的范围（严格限定，与 ADR-0007 不重叠）**：
- ✅ 纠"校对动作出错"：sympy 验算返回 error/异常、`independent_solve` 独立答案明显不合理（量纲错/超物理边界）、格式检查发现问题。
- ❌ 不纠"物理解题过程出错"（建模是否选对模型、列方程是否正确、求解多轮纠错）——那是 ADR-0007 通过替换 `independent_solve._run` 内部实现来解决的。

**理由**：
- 物理流程固定，去掉"首轮自主声明完整 todolist"的空转（相比早期设计的过度设计）。
- 保留 `plan_update` 作进度标记 + 纠错回退点：固定流程的确定性 + 校对动作出错时的打回重做能力，二者兼得。
- 反思范围严格限定在校对动作，与 ADR-0007 的解题纠错边界清晰、不重叠。

**与早期过度设计的对比**：
| 项 | 早期设计（过度） | 本版（精简） |
|----|----------------|-------------|
| 计划结构 | LLM 首轮自主声明完整 9 步 | prompt 写死固定流程 |
| plan_update 用法 | 自主规划 + 动态插入/重排 | 逐步进度标记 + 纠错回退 |
| 自主判断 | 全程规划 | 仅"是否难题→是否独立解题"一处 |
| 反思纠错 | 无（纯单次，设计不足） | 标记前反思，只纠校对动作 |
| 反思与解题纠错边界 | 无 | 校对动作纠错（本 ADR）vs 解题过程纠错（ADR-0007） |

### 决策 2：PlanUpdateTool 用法调整——进度标记 + 学科化自检

**选择**：PlanUpdateTool 在物理的用法从"自主规划"调整为"逐步进度标记"，自检 nudge 并入 prompt 的输出前自检段（决策 1 第 9 步），不强制靠工具触发。

**调整点**：
- 物理不再要求 LLM"首轮调用 plan_update 声明完整计划"——固定流程已在 prompt 写死。
- LLM 每完成一步调用 `plan_update` 标记该步 completed（进度标记，供 UI 渲染 + 作纠错回退锚点）。
- 全部 completed 时的自检 nudge 内容并入 prompt 第 9 步的"输出前自检"要求（解析已实算？独立答案已比对？量纲已校验？标记数=原因数？），不依赖工具返回的 nudge 触发。

**实现方式**：PlanUpdateTool 保留可选 `nudge_template` 注入点（语文仍用工具 nudge）；物理场景下 nudge 可为空或弱化，自检靠 prompt。语文用法不变。

**理由**：物理流程固定，自检作为固定流程的最后一步写在 prompt 里即可，不必依赖工具 nudge 触发；进度标记的 UI 价值保留。语文流程不固定，仍靠工具 nudge。

### 决策 3：独立解题作为可替换接口——`independent_solve` 工具（轻量实现）

**选择**：新增 `independent_solve` 工具，作为第 6 步的实现，其**内部实现可替换**。

**早期（轻量）实现**：
- 主 agent 调用 `independent_solve`，传入「去掉答案的题目」+ 主 agent 生成的解题 prompt。
- 工具**内部新开一份干净的 messages**（无主对话历史、无已见答案的污染），发起**单次 API 调用**，让一个无上下文的大模型一次性解题。
- 返回独立答案给主 agent，主 agent 在第 7 步综合评判。

**工具契约（可替换接口）**：
```
independent_solve(question_without_answer: str, solve_prompt: str) -> {answer, reasoning, ...}
```
- 签名稳定：接收"去答案题目 + 解题 prompt"，返回"独立答案"。
- 落盘：独立解题过程写入 `_物理求解.md`（独立解答案 + 解题 reasoning）。
- **内部实现可替换**：早期是单次 API；未来 ADR-0007 的完整 ReAct 自主解题 agent 开发后，**只替换 `independent_solve` 工具的 `_run` 内部实现**（单次 API → ReAct 解题循环），工具签名、第 6/7 步的调用方式、todo list 全部不变。

**理由**：
- 用工具而非系统层自动触发，让"独立解题"成为主 agent 显式调用的、可观察的一步，符合 ReAct 框架且落盘可追溯。
- 独立解题用干净上下文，避免主 agent 已看到答案造成的判断污染——这是"独立重算"能发现答案错误的根本前提。
- 接口与实现分离：早期轻量上线、快速见效；未来重投入做完整解题 agent 时，校对主流程零改动。

**备选方案**：
- **系统层自动触发**（检测 todo 含独立解题项时系统编排）：接口在系统层、可替换性需额外设计、且不在 ReAct 工具链里可观察性差，pass。
- **主 agent 自己解**（不剥离上下文）：主 agent 已见答案，判断被污染，失去独立重算意义，pass。

### 决策 4：新增结构化中间产物 `_物理求解.md`

**选择**：物理校对新增 `_物理求解.md`，由 `independent_solve` 工具调用写入，记录独立解题过程。

**内容结构**：
```markdown
# 物理独立求解过程（第N题）

## 独立解题输入
- 去答案题目：...
- 解题 prompt：...

## 独立解答案
- 最终答案：8 m/s
- 解题过程（reasoning）：...

## 答案比对
- 题目答案：9.8 m/s
- 独立解：8 m/s → ❌ 不一致（已在校对报告中标记为答案错误）
```

**理由**：满足 CLAUDE.md 中间产物保留要求；排查大题答案判错时可直接看到"独立解是多少、和题目答案差在哪"。

**备选方案**：
- 追加到 `_校对报告.md` 末尾：结构化程度低、与校对结论混在一起难分离，pass。
- 不额外落盘：违反 CLAUDE.md 要求、排查靠翻对话历史，pass。

### 决策 5：工具循环阈值微调

**选择**：物理 `max_loops` 从 25 适度上调；`independent_solve` 加入空结果检测白名单。

- 物理 `max_loops` 从 25 调到 **30**（todo list 含独立解题步骤，工具调用略增，但无纠错循环，不需激进上调）。
- `independent_solve` 加入 `_NAV_CONTROL_TOOLS` 白名单（其结果不应计入 `empty_streak`，避免独立解题返回触发误判）。
- 语文保持不变。
- **注**：激进的阈值放宽（`empty_streak` 3→5、`max_loops` 30→40）与大规模白名单扩展，是 ADR-0007 纠错闭环的需求，不在本 ADR。

**实现方式**：`call_api` 增加 `max_loops` 学科化传参能力（已有参数，按学科传值即可）；`_NAV_CONTROL_TOOLS` 扩展加入 `independent_solve`。

### 决策 6：物理 prompt 重写——区分"代入验证"与"独立解题"两种场景

**选择**：重写物理 `agent_prompt.json`，明确两种答案校验场景：

- **代入验证（第 5 步，默认）**：用 sympy 工具实算验证题目解析里的计算步骤对不对。
- **独立解题（第 6、7 步，仅难题）**：去掉答案、干净上下文独立解一遍、比对。

**难题判定由 LLM 自判**：prompt 写入明确判据，LLM 在执行 todo 第 5 步时自行判定是否插入第 6 步。判据：

> 含以下任一 → 插入独立解题步骤：多个物理过程/状态、电磁场/电磁感应、能量/动量转化、复杂受力分析。否则 → 仅做代入验证。

**备选方案**：
- **程序启发式硬判**（关键词扫描题干硬性路由）：不依赖 LLM 但易误判、维护成本高，pass。
- **全部独立解题**（不区分大小题）：小题耗时与成本无谓增加，pass。

### 决策 7：为 ADR-0007 预留可扩展接口

**选择**：本 ADR 的 `independent_solve` 工具签名设计为稳定接口，明确标注其内部实现将在 ADR-0007 被替换为完整 ReAct 自主解题 agent。

**接口契约**（见决策 3）：`independent_solve(question_without_answer, solve_prompt) -> {answer, reasoning, ...}`，签名不随实现变化。

**预留点**：
- `_物理求解.md` 的结构预留"求解过程"扩展位——未来 ADR-0007 的多轮求解记录可增量写入，不破坏现有结构。
- 物理工具集分层：通用 sympy 工具（evaluate/solve_equation/solve_physics_formula/dimensional_analysis/vector/circle）留在主 agent；为解题 agent 服务的编排/建模工具（verify/finalize/physics_model/physics_solve_chain）归 ADR-0007，不提前塞进本 ADR。

**理由**：避免在本 ADR 提前引入纠错闭环的复杂度（4 个编排工具 + 激进阈值），让物理校对尽快用轻量独立解题见效；同时保证未来重投入解题 agent 时，校对主流程与接口零改动。

## 后果

### 正面
- 物理校对回归"固定流程"本质，去掉自主规划的空转，流程确定性高。
- 难题通过独立解题（干净上下文）能发现"题目答案本身错了"这类核心问题，代入验证永远发现不了。
- 标记前反思补上"校对动作出错时打回重做"的能力（早期纯单次设计不足之处），范围严格限定在校对动作，不与 ADR-0007 解题纠错重叠。
- `independent_solve` 作为可替换接口，早期轻量见效、未来 ADR-0007 替换实现时校对主流程零改动。
- 物理独立解题过程结构化落盘，排查大题答案判错可看到独立解与题目答案的差异。
- 学科差异化合理：语文用 plan_update 自主规划（流程不定），物理用固定流程+进度标记（流程固定），不破坏 ADR-0005 架构。
- 不提前引入解题纠错闭环复杂度，改动面可控、可快速上线。

### 负面
- 早期轻量独立解题仍是单次 API，对极复杂大题单次解题错误率仍在——这正是 ADR-0007 要解决的，本 ADR 用落盘 + 人类抽查兜底。
- 新增 1 个物理工具 + prompt 重写，prompt 变长，注意力稀释风险（需控制 prompt 密度）。
- `_NAV_CONTROL_TOOLS` 扩展，需保证对其他学科无影响（`independent_solve` 物理专用，语文不加载）。

### 风险
- 难题判定由 LLM 自判，存在误判风险（把大题当小题跳过独立解题，或反之小题也独立解题浪费成本）。prompt 判据需明确，issue 拆分时安排大题/小题各一例回归测试。
- 轻量独立解题的单次错误率天花板：极复杂大题单次解可能也错，主 agent 据错误独立解下判断会误判。**缓解**：`_物理求解.md` 落盘 + 人类抽查；未来 ADR-0007 用多轮纠错降低单次错误率。
- 反思机制只纠"校对动作出错"，拦不住"独立解题过程本身解错"（如建模错导致独立答案错）——这是与 ADR-0007 的明确边界，本 ADR 靠 `_物理求解.md` 落盘 + 人类抽查兜底。
- 反思打回重做若失控可能增加轮次，需靠 `max_loops=30` 兜底；反思判据（什么算"上一步结果有问题"）需在 prompt 写清，避免 LLM 反复打回同一步。
- 主 agent 生成解题 prompt 的质量影响独立解题效果——prompt 模板需在 issue 拆分时打磨。
- prompt 重写后需保留旧 prompt 作 fallback 做 AB 对比（沿用 ADR-0005 的 fallback 约定）。

## 不纳入

- **完整 ReAct 自主解题 agent（多轮纠错闭环）** → 移至 [[ADR 0007]]，仅设计、不实现。本 ADR 仅用轻量单次 API 独立解题，并通过 `independent_solve` 接口为 ADR-0007 预留替换点。
- 物理前置搜索（物理目前无类似语文识典古籍的权威原文源，暂不建）。
- 物理图像/图表内容的自动解析（受力图、电路图、v-t 图的图像理解仍靠 LLM 多模态能力）。
- 跨学科校审子 agent（沿用 ADR-0005 不纳入）。
- 其他学科（化学/数学等）的学科化重构——本 ADR 仅针对物理，待物理验证后再推广。
