# ADR 0009：高中语文知识类校对维度叠加架构

**状态**：提议中
**日期**：2026-06-30
**决策者**：MikeTheWiTness
**相关 ADR**：[[ADR 0005 ReAct 机制核心架构]](0005-react-mechanism-architecture.md)、[[ADR 0008 高中语文校对节点图重构]](0008-chinese-node-graph-proofreading.md)

---

## 背景

ADR-0008 将高中语文**题目**校对从"LLM 自主规划"改为"节点图 + 固定分支 todolist"，效果显著——不同文本类型走不同的固定校对策略，机械检查固化为不可跳过的步骤。

但 ADR-0008 的设计前提是"输入是题目"——题干引导语、选项/答案结构、文本类型标签（论述类/文学类/文言文……）构成了明确的分支判据。**知识类讲义不满足这个前提**：

- 知识讲义的类型维度与文本特征维度正交——同一份写作素材讲义里，古文典故需要原文比对，哲学理论需要术语校验，方法讲解需要逻辑自洽检查
- 无论按"内容出处"（庄子/孟子/尼采）还是按"教学功能"（陈述/论证/指导）分分支，都无法用一个维度覆盖所有情况
- 语文知识类型远比题目类型多样——字音字形表、病句归纳、修辞体系、文言虚词表、诗词意象大全、写作素材讲义……后续还会不断出现新类型

**知识讲义校对不能用 ADR-0008 的单维节点图模型。**

---

## 决策

**知识类校对采用"统一入口 + 维度叠加"架构：LLM 第 0 步评估触发条件，按需组装维度检查项成为 todolist。**

### 统一入口

语文校对不再区分"题目 prompt"和"知识 prompt"。一个 agent_prompt，第 0 步判定"题目 or 知识讲义"：

```
第 0 步：判定输入内容类型
  ├─ 题目 → 走 ADR-0008 节点图（8 条分支）
  └─ 知识讲义 → 评估维度触发条件 → 组装 todolist
```

### 维度清单

每个维度是一个独立的检查能力，有自己的触发条件、检查项、禁用项。LLM 第 0 步对所有维度逐一评估是/否。

**始终启用的维度（语言规范基础层）：**

| 维度 | 认知模式 | 检查项 |
|---|---|---|
| ①-A 结构格式 | 扫读 | 编号连续性、层级一致性、段落完整性 |
| ①-B 标点符号 | 逐字扫描 | 中英文标点混用、引号匹配、书名号规范 |
| ①-C 错别字/漏字/多字 | 通读+理解 | 逐句扫描文字错误 |
| ①-D 病句 | 通读+理解 | 搭配不当、成分残缺、语序不当、句式杂糅 |

**按需组装的维度（内容校对层）：**

| 维度 | 触发条件 | 核心检查项 | 禁用项 |
|---|---|---|---|
| ② 原文比对 | 含古诗词/文言文/经典引文原文 | 与前置参考逐字比对；断句/标点校验 | **禁用错别字扫描**（通假字/异体字为正常现象） |
| ③ 事实准确性 | 含概念定义/术语/出处归属/人名/年代/数据 | 定义是否准确；出处是否张冠李戴；数据是否自相矛盾 | 出处引用仅做内部一致性检查；无法程序验证的出处**标记人工复核**，不硬判 |
| ④ 论证恰当性 | 含"素材→主题/观点"的运用示例 | 引喻是否失义；素材是否被强行贴标签；同一素材在多主题下是否被扭曲本意 | — |
| ⑤ 方法自洽性 | 含分步骤/编号的方法讲解或技巧总结 | 步骤逻辑是否通顺；前后是否矛盾；是否有可操作性 | — |
| ⑥ 嵌入题目 | 含完整题目+解析+答案 | 走 ADR-0008 完整节点图 | — |

四个语言规范维度拆分的原因：**LLM 的认知模式不同**。结构格式是眼睛扫标题行、标点是逐字过但不能被内容分心、错字和病句需要理解句意但粒度和依赖关系不同（病句判断需要先修正错别字）。合并会导致注意力稀释——这与 ADR-0008"机械检查在主内容校对之前"的设计原则一致。

### 组装逻辑

第 0 步完成后，LLM 调用 `plan_update` 声明组装后的 todolist。示例：

```
输入：作文素材讲义（含庄子典故 + 素材运用示例）
触发：①-A ①-B ①-C ①-D ② ④

组装 todolist：
1. 结构格式检查（①-A）
2. 标点符号检查（①-B）
3. 错别字/漏字/多字扫描（①-C）——跳过古文引用部分
4. 病句检查（①-D）
5. 对照前置参考逐字比对典故原文（②）
6. 【主校对】论证恰当性——素材运用是否引喻失义/强行贴标签（④）
7. 格式自检
8. 输出校对报告
```

组装出的 todolist 的步骤数 = 启用的维度数 + 格式自检 + 输出，与 ADR-0008 的分支深度相当（5-8 步），LLM 注意力可控。

### 类型判断的两阶段确认（复用 ADR-0008）

切割阶段 LLM 打类型标记（`<knowledge>` / `<problem-strip>`），但最终裁决权归校对 LLM 的第 0 步。不一致时：

1. LLM 声明怀疑理由
2. 重新审视内容特征
3. 确认后切换（走题目节点图 或 知识维度叠加）
4. 审视后认为原判断无误，继续当前路径

不加额外仲裁 LLM——两阶段确认已在 ADR-0008 验证，最坏情况（误判）不致命（LLM 发现结构与 prompt 不匹配后自动纠偏）。

### 智能切割管线

知识讲义的分割采用"Python 确定性扫描 + LLM 仅处理模糊部分"的管线：

```
步骤 1（Python，零 API）：结构扫描 + 置信度分层
  ├─ HIGH → 直接确定边界（有明确结构标记的块）
  ├─ LOW → 标记"待细分"（同级标题下块过大/缺乏子标记）
  └─ NONE → 整段传递（无任何结构信号的纯文本段）

步骤 2（LLM，仅处理 LOW + NONE）：块分类 + 子边界识别
  输入：区间头尾各 2-3 行（非全文）
  输出：类型标注 + 子边界

步骤 3（Python）：合并步骤 1 的 HIGH 结果 + 步骤 2 的细分结果 → 生成锚点列表

步骤 4（bash 逆序插入 + Python 复核）
  逆序插入标签 → 配对检查 → 空单元检查
```

**不做 LLM 输出全文+标签**（当前 smart_split 模式）——长文档输出窗口压力大，LLM 可能截断或跳过段落。改为 LLM 输出锚点列表（~2K token），Python/bash 执行插入。

**置信度分层**的意义：正常格式讲义（80%+ 高置信度）只走步骤 1→3→4，零 LLM 调用。格式混乱的讲义才触发步骤 2，且只处理混乱部分。

### 人工预处理优先

知识讲义虽然格式不统一，但结构信号密集（`【寓意】` `【适用角度】` `####` 标题等）。人工预处理统一格式是一次性成本，远低于管线无限细化的持续维护成本。格式越规整，管线的 HIGH 置信度覆盖率越高，LLM 调用次数越少。

### 知识手工标记

新增独立标记 `###### 知识开始 ######` / `###### 知识结束 ######`，不复用题目标记。两个标记格式一致但关键词不同，语义自解释，支持嵌套场景（知识块内嵌题目标记）。

### 与 ADR-0008 的对比

| 维度 | 题目校对（ADR-0008） | 知识校对（本 ADR） |
|---|---|---|
| 架构模型 | 单维节点图 → 8 条固定分支 | 统一入口 + 维度叠加 → 按需组装 |
| 前置判断 | LLM 判"文本类型"→ 走哪个分支 | LLM 判"题目/知识" → 评估各维度触发条件 |
| 分支/维度数 | 8 条互斥分支 | 6 个非互斥维度，自由组合 |
| 机械检查 | 嵌入各分支前几步 | 4 个语言规范维度（①-A~D）始终在最前 |
| 计划方式 | plan_update 声明 + 逐步标记 | 同 |
| 反思范围 | 仅格式自检 | 同 |
| nudge_template | 空串 | 空串 |
| max_loops | 15 | 15（最大组装步数 ~8，足够缓冲） |
| 新增工具 | 无 | 无（纯 prompt 层改动） |

### 设计原则——朝向统一入口

本次架构的最终目标是：用户只需发送一个 Word 文档说"校对"，agent 通过多次路由自动找到正确的处理方式。本 ADR 将"题目 vs 知识"的路由判断上移至第 0 步，消除了 `is_knowledge` 的程序硬分支，是朝这个目标的关键一步。

## 后果

### 正面
- 维度叠加模型天然可扩展——新知识类型只需评估"现有维度是否覆盖"，无需新增分支。未覆盖时添加新维度，不影响已有维度
- 统一入口消除 `is_knowledge` 程序分支，用户无需选择模式
- LLM 注意力集中在组装后的 todolist 上，不被无关维度干扰
- 切割管线将 LLM 调用压缩到一次（且仅处理模糊部分），大幅降低 token 消耗和输出截断风险
- 改动面集中在 prompt 层 + 切割管线，`api_client.py`、`plan_tools.py`、`format_enforcement.py` 全部不变

### 负面
- 统一 prompt 比 ADR-0008 更长（需包含所有维度定义 + 触发条件 + 组装逻辑），注意力稀释风险。缓解：维度描述精简，触发条件结构化
- 维度之间的顺序依赖（如 ①-C 必须在 ①-D 之前）增加 prompt 复杂度
- 第 0 步的判断负担比 ADR-0008 更重——需评估 7 个维度触发条件而非选 1 个分支

### 风险
- 维度触发条件过于模糊导致 LLM 漏启用关键维度。缓解：触发条件用明确关键词（"古文引用 = 含《》书名号+文言句式"）而非抽象描述
- 切割管线的 LOW/NONE 置信度区间比例过高 → LLM 调用频率上升。缓解：人工预处理统一格式
- 嵌入题目的适配：⑥ 走 ADR-0008 意味着知识校对流程中嵌套题目校对流程，状态传递可能复杂。缓解：嵌入题目作为独立单元标记 `<problem>`，切割阶段即区分

## 不纳入
- 新增知识专用工具（无需求）
- 出处引用的外部验证（无可用知识库/API，仅做内部一致性检查 + 人工复核标记）
- 切割步骤的 LLM 仲裁（类型不一致时复用现有两阶段确认）
- 其他学科的知识校对（待语文验证后再推广）
