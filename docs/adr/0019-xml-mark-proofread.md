# ADR 0019：XML 标记式校对 —— `<mark_N>` 替代 `【N|原文|改为】`

**状态**：实现中
**日期**：2026-07-07
**决策者**：MikeTheWiTness
**关联**：[[ADR 0016]](0016-tool-generated-proofread-marks.md)、[[ADR 0017]](0017-unified-section-split.md)

---

## 背景

ADR-0016 设计的 `add_proofread_mark` 工具使用 `【N|原文|改为】` 内联替换格式。实际使用中发现：

1. **公式安全性差**：物理/化学等学科的数学公式中 `{` `}` 密集，LLM 改片段时容易产生括号不配对（如 `({R_2}+R})`），导致 LaTeX 编译失败
2. **原文被修改**：替换式标记改变了原文结构，出错后无法恢复
3. **校验复杂**：需要在工具层做 LaTeX 括号平衡检查，仍无法覆盖所有情况

**本 ADR 废弃替换式标记，改用 XML 指针标记 `<mark_N>...</mark_N>`，原文完全不被修改。**

---

## 决策

### 决策 1：XML 指针标记格式

```
原文：          AAAA<mark_1>BBBB</mark_1>CCCC
文档末尾：      ### 修改建议
               <mark_1>: BBBB → XXXX  原因: ...
```

- `<mark_N>...</mark_N>` 仅标记位置，**不修改原文任何一个字**
- 修改建议记录在文件末尾的 `### 修改建议` 章节
- 编号由工具自动递增（`mark_1`、`mark_2`...）
- 下划线分隔提高可读性（`mark_10` vs `mark10`）

### 决策 2：标记必须在公式外部

LLM 必须将 `<mark_N>` 放在 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 外部。公式内有错误时，包裹整个公式块。

错误示例：
```
$x^2 + <mark_1>y^2</mark_1> = z^2$     ← 标记在 $...$ 内
```

正确示例：
```
<mark_1>$x^2 + y^2 = z^2$</mark_1>      ← 标记包裹整个公式
```

### 决策 3：工具自动修复公式内标记

`insert_mark` 写入文件前检测插入位置是否在数学模式内。若是，自动将标记挪到公式边界外：

- `<mark_N>` 在公式内 → 移到 `$` / `$$` / `\(` / `\[` 左侧
- `</mark_N>` 在公式内 → 移到 `$` / `$$` / `\)` / `\]` 右侧
- 成对出现时包裹整个公式块

### 决策 4：新工具替代旧工具

| 新工具 | 功能 | 替代 |
|--------|------|------|
| `insert_mark` | 插入 `<mark_N>` / `</mark_N>`（含自动修复） | `add_proofread_mark` |
| `add_correction` | 追加修改建议到 `### 修改建议` | `update_proofread_mark` 的原因更新部分 |

旧工具保留代码但不再使用。

---

## 影响

### 正面

- **原文零修改**：标记不改变原文内容，公式安全
- **工具极简**：`insert_mark` 只做插入操作，不会产生格式错误
- **自动修复**：LLM 即使把标记放进公式内也会被工具纠正
- **双栏报告兼容**：`<mark_N>` 可渲染为圈号上标，和 `\corrmark` 输出一致

### 负面

- **全链路改造**：9 个模块需要适配新格式（解析、校验、LaTeX 生成）
- **迁移成本**：旧 `【N|原文|改为】` 格式的代码和 agent_prompt 需更新
